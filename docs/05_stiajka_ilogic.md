# Присадка 05 непосредственно внутри Inventor

Правило: `scripts/Создание присадки/05_Stiajka_Native.iLogicVb`.

Это самостоятельное правило iLogic с прямыми вызовами Inventor API. Оно не запускает Python, консольный процесс или старый лаунчер. Подготовлено и проверено компилятором с библиотекой API установленного Inventor 2023. Создание геометрии и скорость необходимо проверить в самом Inventor.

## Запуск

1. Откройте исходную копию детали `.ipt`.
2. Выберите две грани одного тела: узкую грань и пласть с одним общим прямым ребром. Для нескольких тел выберите по две грани каждого тела.
3. В браузере iLogic откройте вкладку внешних правил и добавьте файл `05_Stiajka_Native.iLogicVb`.
4. Запустите это внешнее правило и выберите тот же параметр отступа, который использовали в Python.

Альтернативный способ — создать обычное правило iLogic с одной строкой:

```vb
iLogicVb.RunExternalRule("D:\Копия Google диска\02_Скрипты\01_Скрипты для работы\For Inventor\Присадка кодом Python\scripts\Создание присадки\05_Stiajka_Native.iLogicVb")
```

Либо скопируйте всё содержимое файла, включая `AddReference`, `Imports` и `Public Class ThisRule`, в редактор нового правила. Внешний файл удобнее обновлять и сравнивать.

Существующее `05_Stiajka.iLogicVb` продолжает запускать Python. Для нового варианта выбирайте файл с окончанием `_Native`.

Если папка проекта перенесена, измените константу `ProjectRoot` в начале нового правила.

## Настройки и результат

Правило читает тот же библиотечный JSON:

```text
..\01_inventor_service\service\excel_parameters\part_config.example.json
```

Если существует локальный `settings.json`, он служит резервом; значения библиотечного файла имеют приоритет. Сопоставление `linked_parameters` переводит имена из JSON в реальные имена параметров детали.

Сохраняются основные правила `05_stiajka.py`:

- первая грань определяется по меньшей площади;
- первые эскизы объединяются по совпадающим плоскостям;
- оба контрольных размера измеряют одно общее ребро выбранных граней;
- расстояние между крайними точками кратно 32 мм и зависит от выбранного параметра отступа;
- при расстоянии 64 мм используется один центральный шкант;
- на второй грани создаются два центра чашек со смещением `Стяжка_отступ`;
- все эскизы готовятся до создания отверстий;
- соседнее тело ищется по совпадающей грани и всем центрам сверления, включая скрытые тела;
- торцевые отверстия и чашки ограничиваются телом выбранных граней, отверстия штока в боковину и шканта в пласть — соседним телом;
- диаметры, глубины и направления берутся из тех же блоков JSON;
- глубина чашки берётся из `stiajka.parameters.depth`, как в Python, даже если `Chashka stiajki.depth_parameter` содержит другое значение;
- создаются новые эскизы и операции, использованные эскизы скрываются.

Весь запуск оформлен одной транзакцией. При ошибке правило пытается отменить все изменения этого запуска. После успешного запуска его можно отменить одной операцией Undo. Если отмена не удалась, ошибка записывается в журнал.

## Сравнение скорости

Журнал нового правила: `05_stiajka_ilogic.log` в корне проекта.

Журнал Python: `05_stiajka.log`.

Сравнивайте строки:

| Этап | Оба журнала |
|---|---|
| Первые эскизы | `Первые эскизы` |
| Вторые эскизы | `Вторые эскизы` |
| Поиск соседей | `Поиск соседних тел` |
| Все отверстия | `Все отверстия` |
| Обновление | `Обновление документа` |
| Итог | `05: Общее время построения` |

Итоговый таймер запускается после выбора и подготовки параметров. Ожидание окна выбора и первая компиляция iLogic в него не входят. Время завершения транзакции и восстановления перерисовки входит в итог iLogic.

Используйте одинаковую исходную геометрию, выбранные грани, параметры и настройки. После каждого замера возвращайте деталь к исходному состоянию; повторный запуск поверх уже созданной присадки меняет и геометрию, и условия измерения. Для Python проще использовать исходную копию детали, поскольку его изменения создавались несколькими операциями.

Полезно сделать несколько замеров и сравнить среднее или медиану. При сравнении также проверьте число операций, расположение центров, оба контрольных размера и затронутые тела.

## Проверка кода без изменения модели

```powershell
python -X utf8 -B scripts\validate_ilogic_native.py --smoke
```

Проверка компилирует VB.NET с `Autodesk.Inventor.Interop.dll` из установленного Inventor 2023 и выполняет чистые функции .NET: чтение настроек, сопоставление имён с Python, расчёт расстояний и отказ при недостатке места. Она не запускает правило на документе и не заменяет проверку геометрии в Inventor.

При другой папке установки укажите `--inventor-dir`. Правило использует `System.Web.Extensions.dll`, доступную в .NET Framework Inventor 2023; для будущих версий Inventor на другой платформе .NET зависимости следует проверить отдельно.

Использование Inventor API и явного класса `ThisRule` описано в [руководстве Autodesk по расширенным правилам iLogic](https://help.autodesk.com/cloudhelp/2025/ENU/Inventor-iLogic/files/GUID-32B66838-22E4-4A0A-B5BB-862350C76B36.htm). Вызов внешнего правила по пути описан в [справке RunExternalRule](https://help.autodesk.com/cloudhelp/2026/ENU/Inventor-iLogic/files/GUID-07DA57D0-B34C-49D8-8B44-5C554A07C359.htm).

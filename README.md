# Автоматизация мебельной присадки в Autodesk Inventor

Python-скрипты для создания эскизов и отверстий мебельной присадки в активной детали Autodesk Inventor через COM.

Основной рабочий режим: перед запуском команды пользователь вручную выбирает нужные грани в Inventor. Скрипт читает выбранные грани, строит служебные эскизы, создаёт отверстия и скрывает использованные эскизы.

## Требования

- Autodesk Inventor уже запущен.
- Открыта активная `.ipt`-деталь.
- Перед запуском команды в Inventor выбраны нужные грани.
- Установлены Python и `pywin32`.
- Python и Inventor запущены с одинаковыми правами пользователя, иначе COM-подключение может не сработать.

## Быстрый Запуск

Стяжка 2 шт.:

```powershell
python 05_stiajka.py
```

Конфирмат 2 шт.:

```powershell
python 02_confirmat.py
```

Через консольный лаунчер:

```powershell
scripts\launcher.bat stiajka
scripts\launcher.bat confirmat2
```

Через оконный лаунчер для iLogic:

```powershell
pythonw scripts\launcher_window.py stiajka
pythonw scripts\launcher_window.py confirmat2
```

iLogic-правила лежат в папке:

```text
scripts\Создание присадки
```

## Источник Настроек

Главный источник истины для технологических настроек присадки находится в подключаемой библиотеке:

```text
..\01_inventor_service\service\excel_parameters\part_config.example.json
```

Этот JSON формируется библиотечным проектом из нужного Excel. Из него берутся блоки:

- `drilling`
- `confirmat`
- `stiajka`
- `linked_parameters`

Проектный файл `settings.json` больше не является главным источником. Он может отсутствовать. Если он есть, он используется только как локальный fallback, а значения из библиотечного JSON имеют приоритет.

Резервная копия локальных настроек может лежать как:

```text
settings.local.backup.json
```

## Runtime-Параметры Inventor

Некоторые параметры относятся не к библиотеке, а к конкретной активной детали Inventor. Они выбираются явно в выпадающем окне при запуске скрипта:

- `Толщина_каркаса`
- `Минимальный_отступ_присадки_от_кромки_Каркас`
- параметр количества конфирматов, например `Кол_конф`

Если нужного параметра нет в активной детали, скрипт покажет список отсутствующих параметров и остановится.

Скрипты добавляют/обновляют служебный параметр `Keep_Excel_Params`, чтобы удерживать импортированные из Excel параметры от удаления Inventor.

## Как Работает `05_stiajka.py`

Скрипт создаёт стяжку по выбранным граням.

Можно выбрать:

- 2 грани на одной детали: узкая кромка + большая пласть;
- 4 грани на двух деталях/телах: по две грани на каждой детали.

Для каждой пары скрипт сам определяет:

- меньшую грань как первую узкую грань;
- большую грань как вторую грань пласти.

При каждом запуске создаются новые эскизы на первых и вторых гранях; существующие эскизы сохраняются. На первой узкой грани создаётся эскиз сверления как в общей логике drilling. Затем создаются отверстия стяжки/шкантов по настройкам библиотеки.

Если расстояние между крайними точками равно 64 мм, команда `05` создаёт две стяжки и один центральный шкант: внутренние точки с отступом 32 мм совпадают и используются как один центр отверстия. Например, это применяется к грани длиной 120 мм при минимальном отступе 20 мм. При расстоянии меньше 64 мм команда останавливается с сообщением о недостатке места. Ошибки и этапы запуска сохраняются в `05_stiajka.log`.

Все эскизы подготавливаются до создания отверстий, чтобы перестроение тела не нарушало ссылки на выбранные грани. На второй грани создаются только два центра отверстий, связанные симметрией и параметром расстояния. Во время построения перерисовка Inventor временно отключается и восстанавливается при завершении или ошибке. Журнал содержит время первых и вторых эскизов, отверстий, обновления документа и общее время построения без ожидания выбора параметра.

Команда `05` использует объекты новых проекций напрямую, без повторного поиска линий по границам граней. Свободные имена эскизов и параметров подбираются точечными запросами и запоминаются до конца запуска, без повторного перечисления всей коллекции. Во втором эскизе линия отступа одновременно служит осью симметрии. Для первых эскизов отдельно измеряются проекция рёбер, подготовка геометрии, оси, точки и зависимости, размеры и имена, а также обновление решателя эскиза.

Контрольные размеры `Long_edge_*` в обоих эскизах пары измеряют проекцию одного общего прямого ребра на пересечении выбранных граней. Значения размеров одинаковы и зависят от реального ребра модели; имена параметров остаются уникальными. Формулы расстояния между крайними точками используют эти размеры. Если общее ребро занимает только часть границы второй грани, её полный габарит в расчёт не подставляется. При отсутствии единственного общего прямого ребра команда останавливается до построения эскизов и отверстий.

Отверстия команды `05` создаются через `stiajka/hole_builder.py`. Имена операций подбираются точечными запросами и запоминаются на время запуска. Для каждой операции в журнал отдельно выводятся подготовка точек и размещения, создание отверстий в Inventor, подбор и назначение имени, назначение затрагиваемого тела.

Каждая операция команды `05` ограничена одним телом. Для отверстий штока в боковину (`Otv_stijki_v_bokoviny`) и шканта в пласть (`shkant_v_plast`) выбирается соседнее твёрдое тело с гранью, совпадающей с первой выбранной гранью. Проверяется принадлежность всех центров сверления реальной грани соседа, включая её границы и вырезы. Торцевые отверстия и чашки ограничиваются телом выбранных граней. Если сосед не найден или найдено несколько тел, команда останавливается до сверления. Пакеты разделяются по целевым телам и исходным эскизам. Если назначить единственное тело операции не удалось, эта операция удаляется и выполнение останавливается; переход к воздействию на все тела не выполняется.

Поиск соседа использует `PartComponentDefinition.FindUsingPoint` сразу во всей детали, включая скрытые тела. Обход коллекции тел и чтение их `RangeBox` не выполняются. Среди всех граней у центра сверления проверяются плоскость и принадлежность остальных центров через `GetClosestPointTo`. Если первая точка не дала подходящей грани, поиск повторяется на следующих центрах; неоднозначный выбор отклоняется. В журнал отдельно выводятся время перевода центров в координаты модели, поиск граней и проверка кандидатов, число запросов и найденных граней.

Координаты концов проекционных отрезков читаются один раз при подготовке каждого эскиза. Выбор боковых рёбер и расчёт их длин выполняются по этому числовому снимку. В новом первом эскизе `05` не создаётся прежняя дополнительная линия боковой плоскости, которая не участвует в привязке отверстий. Контрольный размер по общему ребру, оси и зависимости центров сохраняются.

Во время построения `05` использует `common/cached_sketch.py`: коллекции точек, линий, геометрических зависимостей и размеров запрашиваются один раз на эскиз. Координаты середин и вспомогательных точек сохраняются в числах Python для повторных расчётов. Положение и зависимости осей и центров остаются прежними. Для выбора стороны смещения второго эскиза преобразуется одна внутренняя точка `Face.PointOnFace`, без чтения всех вершин грани. Кэши ограничены одним эскизом и не передаются между запусками.

На время команды `common/runtime_service.py` сохраняет ссылки на `TransientGeometry` и `TransientObjects`. Типы и координаты исходных рёбер, прочитанные при поиске общего ребра, используются повторно при проецировании обеих граней. Найденные ссылки на тела передаются построителю отверстий; после перестроений проверяется имя тела, а при недействительной ссылке выполняется резервный поиск. Для повторно используемых центров один раз выполняются проверка уникальности, установка `HoleCenter` и создание коллекции точек. Определение размещения отверстий создаётся отдельно для каждой операции. Все эти кэши действуют в пределах одного запуска.

Окно отступа команды `05` сначала читает только пользовательские параметры. Для доступа к параметрам модели нажмите «Загрузить параметры модели»; текущий выбор при загрузке сохраняется. Объекты параметров, полученные при чтении списка, используются повторно для проверки наличия и чтения значений. Кэш действует только до конца запуска; в следующем запуске значения читаются заново. Формула `Keep_Excel_Params` записывается только при изменении или отсутствии параметра. В журнал отдельно выводятся инициализация параметров, чтение списков, проверка наличия, подготовка `Keep_Excel_Params` и чтение отступов. Эти замеры не включают ожидание выбора пользователя в окне.

На второй большой грани создаётся отдельный эскиз. Вспомогательная линия с точками располагается параллельно линии пересечения выбранных граней и смещается от первой плоскости на значение параметра `Стяжка_отступ`. Отверстия создаются по двум крайним точкам:

- диаметр: `Стяжка_D`;
- глубина: `Стяжкаh_резьбаШтока_Петля`.

## Как Работает `02_confirmat.py`

Скрипт создаёт конфирматы по выбранным граням.

При запуске он запрашивает:

- параметр толщины материала;
- параметр минимального отступа от кромки каркаса;
- параметр количества конфирматов.

Затем создаёт новые смещённые эскизы, точки сверления и отверстия конфирмата. Существующие эскизы не используются повторно и не удаляются. Если количество конфирматов равно `2`, центральная операция создаётся с условием подавления по выбранному параметру количества.

Основной алгоритм находится в `02_confirmat.py`, окно выбора — в `confirmat/parameter_dialog.py`, подготовка параметров — в `confirmat/parameters.py`, операции отверстий и подавления — в `confirmat/confirmat.py`. Этапы и ошибки видны в окне лаунчера; отдельный журнал скрипт не создаёт.

## Эскизы Сверления

Для выбранной грани строится:

- ось по центру двух коротких рёбер;
- пять точек на оси: левая крайняя, левая внутренняя, центральная, правая внутренняя, правая крайняя;
- размеры и зависимости, привязанные к пользовательским параметрам отступа.

Шаг между точками кратен `32 mm`.

Расстояние между крайними точками считается по формуле:

```text
floor((Long_edge_N - отступ * 2) / 32 mm) * 32 mm
```

Используется выбранный пользователем параметр отступа от кромки каркаса.

Цвет рабочих эскизов сверления: `RGB (255, 220, 0)`.

## Проверки

Проверить синтаксис Python-файлов:

```powershell
python -m compileall -q .
```

Проверить подключаемый библиотечный JSON:

```powershell
python -m json.tool ..\01_inventor_service\service\excel_parameters\part_config.example.json
```

Полную функциональную проверку нужно делать в Inventor на копии детали, потому что скрипты создают реальные эскизы и отверстия в активном документе.

## Важно

- Перед запуском рабочей команды обязательно выделите грани в Inventor.
- Для стяжки выбирайте пару граней на каждой детали: узкая кромка + большая пласть.
- Для двух деталей выбирайте 4 грани: по две на каждой детали.
- Рабочие скрипты скрывают использованные эскизы после создания отверстий.
- Перед массовым запуском проверяйте результат на копии детали.

## Размер выбранных отрезков эскиза

1. Откройте 2D-эскиз детали для редактирования.
2. Выделите отрезки, длина которых должна управляться одним параметром.
3. Запустите iLogic-правило `06_LineParameter.iLogicVb`.
4. Выберите параметр длины и нажмите «Применить».

Команда меняет существующие размеры длины либо добавляет новые. Размеры получают выражение с именем выбранного параметра, поэтому продолжают зависеть от него. Каждый отрезок обрабатывается отдельной транзакцией: при ошибке отменяется только его изменение, успешные назначения остальных отрезков сохраняются. Размеры эскиза включаются для отображения. В окне запуска выводятся сохранённые и пропущенные отрезки. Проекционные линии не изменяются; существующие геометрические зависимости не удаляются. Если линии уже связаны равенством или фиксированы, добавление управляющего размера может быть отклонено Inventor.

Запуск без iLogic: `python 06_line_parameter.py` или `scripts\launcher.bat line_parameter`.
